# ShellX Cut Test Rigs

The normal Rust workspace runs every hermetic test. Remaining `#[ignore]` tests
are listed in `scripts/release/ignored-test-rigs.json`; the manifest is checked
against the Rust source so an unclassified exclusion fails the normal Node gate.

List the current rigs:

```bash
node scripts/ignored-test-rig.mjs --list
```

Run one rig from a clean source tree:

```bash
node scripts/ignored-test-rig.mjs --id <rig-id> --out <private-receipt-dir>
```

The runner checks the declared platform, commands, paths, environment, and input
artifacts before starting. It refuses a dirty Git tree unless `--allow-dirty` is
passed for non-release debugging. Declared output directories must already
exist, and output files must not; this prevents stale artifacts from passing as
fresh evidence. Perception rigs automatically bind the checked-out
`app/perception/py` payload and, when the rig requires it, that payload's
platform-specific `.venv` Python. Explicit `SHELLX_CUT_SIDECAR_DIR` and
`SHELLX_CUT_PYTHON` overrides still take precedence.

Every receipt records the app version, exact Git commit, Cargo.lock hash,
platform, command, compiled Rust test-binary hash, input/output artifact hashes,
and stdout/stderr hashes. Release evidence must use clean-tree receipts stored
outside the public export.

Installed-app release qualification is a separate native-platform layer. Run
`scripts/windows/install-cut-current.ps1` on Windows,
`scripts/macos-installed-walkthrough.mjs` on macOS, and
`scripts/linux-wdio-full-coverage.mjs --installed-final` on native Linux. These
gates bind the installed version, source-content digest, shipping-artifact hash,
all canonical bundled agent documents through `/api/agent-doc/*path`, Settings,
Library, About, Debug API, and the MCP self-test. Linux qualification is not
valid from WSL.

## Final installed all-actions qualification

Immediately before release, run one complete installed-app UI qualification on
each supported surface: macOS, Windows, and native Linux. This is one final
pre-release gate across the three surfaces, not an informal check after each
feature and not a collection of partial receipts.

The wrapper invocation is:

```bash
FCV_REQUIRE_FULL=1 \
FCV_INSTALLED_APP=1 \
FCV_UI_DRIVER=<native-installed-driver> \
FCV_ACTION_MANIFEST=ui/public-tests/full-ui-action-manifest.json \
node scripts/release/full-coverage-gate.mjs --final-all-actions
```

The environment must not define `FCV_SECTION`, `FCV_ONLY`, or `FCV_NO_AGENT`.
The action manifest must match the observed registry exactly, and every action
row must pass all four dimensions: `PRESENT`, `RENDER`, `CLICK`, and `RESULT`.
A second runtime manifest is mandatory: the driver records stable source-action
identities from real `click`, `input`, and `change` events, and that observed set
must exactly match the committed source manifest. Static selector ownership or a
passing support row cannot substitute for actuating a control.
A candidate WebDriver build, development server, filtered section, or
candidate-only receipt cannot satisfy installed release proof. The committed
manifest is the strict source/native inventory (currently generated by
`node scripts/update-ui-action-manifest.mjs`); the receipt separately hashes
the unique runtime actions and every repeated action occurrence.

The wrapper accepts the installed Windows WebView2 CDP adapter and official
external Tauri WebDriver on native Linux. The Linux runner builds the normal
shipping package, extracts that exact `.deb`, hashes the package plus binary,
and drives it without the `webdriver-test` feature:

Run the Windows gate on an unattended, unlocked Windows desktop session that is
reserved for qualification. Do not run it on a machine where a person is
typing or switching windows: native Common Item Dialog input is foreground
sensitive. The Windows wrapper refuses session 0, locked sessions, and sessions
without Explorer. Its native action helper also refuses to type or send keys
unless the foreground dialog belongs to `shellx-cut`; a focus change is a test
failure, never a reason to force focus or continue with ambiguous evidence.

Run the wrapper from WSL in that interactive Windows session:

```bash
node scripts/windows-installed-full-coverage.mjs \
  --unattended-native-ui \
  --signed-final \
  --scene <real-scene-video> \
  --speech <real-speech-video> \
  --face <real-moving-face-video> \
  --speakers <real-multi-speaker-video> \
  --second <real-second-video> \
  --clean-after
```

The wrapper launches the exact installed shipping executable with the narrow
`SHELLX_CUT_WEBVIEW2_DEBUG_PORT` opt-in. The shell accepts only a valid port and
otherwise uses Wry's normal WebView2 arguments. A second narrow token gives the
run its own WebView2 data directory under
`%LOCALAPPDATA%\ShellX Cut Qualification`; `--clean-after` removes that exact
profile. Readiness and the Playwright
sweep run under native Windows Node, not WSL Node, so Windows loopback CDP,
cutd, native paths, and Common Item Dialog control all belong to the same OS
session. The source receipt records the verifier runtime and CDP opt-in. This is
a rig-only debug path; it adds no user setting, public verb, or agent workflow.

```bash
node scripts/linux-wdio-full-coverage.mjs \
  --host your-linux-ssh-alias \
  --installed-final \
  --scene-clip <real-scene-video> \
  --speech-clip <real-speech-video> \
  --face-clip <real-moving-face-video> \
  --speakers-clip <real-multi-speaker-video> \
  --second-clip <real-second-video> \
  --tauri-driver <path-to-tauri-driver> \
  --webkit-driver <path-to-WebKitWebDriver> \
  --clean-after
```

Windows and Linux emit `installed-runtime-receipt.json`,
`installed-artifact-integrity.json`, and `installed-walkthrough-receipt.json`
only after the strict installed action matrix passes. Native signature/package
checks run before and after qualification, the shipping binary hash must remain
unchanged, and port 4445 must refuse connections both while the app is running
and after it exits.

Use `--clean-after` for the final macOS, Windows, and Linux runners. It preserves
receipts, screenshots, package hashes, and retained shipping artifacts while
removing rebuildable Cargo/UI outputs, extracted packages, isolated app
profiles, staged media, and throwaway projects. Inspect active processes and
reconcile retained evidence before separately pruning older run directories.

When a remote rig has the Claude CLI but no persisted login, set the standard
`ANTHROPIC_API_KEY` environment variable for the runner. If present, the value
is streamed over SSH stdin into the one test process tree; it is never placed in
argv, written to the rig, or included in receipts.

The official Tauri driver has no external WKWebView backend on macOS, so the
macOS gate is deliberately paired rather than mislabeled as installed DOM
automation. First run the complete same-source instrumented candidate matrix:
macOS remains release-red until both halves of this exact-source pair pass.

```bash
node scripts/macos-wdio-track-controls.mjs \
  --host your-mac-ssh-alias \
  --suite full-coverage \
  --strict-candidate-actions \
  --real-screen-record \
  --clean-after
```

That receipt must remain `installedApp:false`. Then build, sign, notarize, and
staple the normal shipping app from the same frozen source and run this command
on the Mac:

```bash
SOURCE_COMMIT=$(git rev-parse HEAD)
SOURCE_CONTENT=$(node scripts/source-content-manifest.mjs --sha256)
node scripts/macos-installed-walkthrough.mjs \
  --app <notarized-ShellX-Cut.app> \
  --out <private-evidence-dir> \
  --source-commit "$SOURCE_COMMIT" \
  --source-content-manifest "$SOURCE_CONTENT"
```

The shipping walkthrough proves the exact 23 installed agent documents,
Settings, Library, About, Debug API registry parity, MCP same-engine behavior,
an on-screen screenshot or CoreGraphics proof for every opened surface, absence
of the embedded WebDriver port, unchanged app-bundle digest, and passing
codesign, Gatekeeper, and stapler checks before and after use. Release
qualification requires both halves from the same source; neither half waives
the other.

The classifications are:

- `perception_runtime`: provisioned Python/model runtime and generated media.
- `real_media`: large source media and writable artifact storage.
- `hardware`: a named GPU or other hardware capability.
- `permission`: an interactive OS device/permission surface.
- `authenticated_service`: a logged-in external service with explicit quota use.
