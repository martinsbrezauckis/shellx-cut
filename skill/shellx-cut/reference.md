# ShellX Cut — verb reference

> **v0.6.107 current.** Synced to `schema/verbs.json`, which is the
> machine-readable contract for all REST, MCP, CLI, debug, and agent calls.
> Current contract: **262 verbs across 32 domains**. If this table and the schema
> disagree, trust the schema and update this reference in the same change.
> Each entry's `behavior` metadata is executable: it names exactly one mutation
> class, its project-state requirement, direct bounded engine-interaction flags,
> generated dispatch target, idempotency/replay/job/risk/UI facts, and Agent Chat
> capability. `filesystem` includes reads as well as writes of registered
> project/asset/index paths; `process` includes bounded local helpers such as
> ffmpeg; `ui` includes a desktop bridge or OS permission-prone native probe.
> `replayable` applies only to durable project mutations, and `async_job` means
> this verb starts/owns a job rather than merely reporting one. Agent Chat capability controls filtered MCP exposure, not whether a
> permitted Cut handler is pure. `timeline` is the only undo-history class;
> unknown journal verbs fail closed rather than becoming implicit timeline edits.
>
> **Current high-signal surfaces:** native editable Generate (`generate.*`),
> CLI-backed media generation (`assets.generate`), dubbing (`audio.dub`),
> diarization (`media.diarize`), Canary + MMS_FA timestamped STT, compact
> Environment setup cards, Library reuse workflows, and debug verbs for visible
> UI control.
>
> **Runtime notes:** renders are memory-bounded by default.
> `SHELLX_CUT_RENDER_GPU=1` is an experimental opt-in GPU path; software render
> remains the receipt-exact baseline. See `SKILL.md` for operational environment
> details.

## Invocation

- REST: `POST http://127.0.0.1:6161/api/verb/{name}` — body is the args JSON.
  6161 is the default; `cutd serve --addr 127.0.0.1:<port>` or an installed app
  fallback rebinds on loopback only. Direct REST callers must substitute the
  actual loopback URL reported by the running app/server.
- MCP: `cutd mcp` (stdio) — **proxies the running `cutd serve`**.
  `cutd serve` writes live address discovery when it binds a non-6161 port, and
  MCP uses that live address before falling back to 127.0.0.1:6161.
  `--standalone` opens its own project only when no server runs. Tool names map dots→underscores:
  `transcript.cut_words` → `transcript_cut_words`.
- CLI: `cutd verb <name> '<args json>'` — one-shot escape hatch using the same
  live server discovery as MCP.
- Convenience GETs: `GET /api/verbs` (registry), `GET /api/state`,
  `GET /api/frame?at_ms=`, `GET /api/events` (WS).
- Installed-agent docs: `GET /api/agent` returns the bundled discovery index;
  its `read_first` list includes
  `/api/agent-doc/docs/public/DEBUG_API.md` for the endpoint and security contract
  shipped with that build.

**Local trust contract:** the supported default is one personal workstation /
one trusted interactive environment. The unauthenticated loopback API is a
whole-machine boundary, not same-user isolation: any local process or OS account
able to connect can operate the open editor. Origin/Host checks are browser
cross-origin/DNS-rebinding mitigations, not native caller authentication. The
MCP proxy inherits the same boundary; the contained Claude `agent.chat` broker
only limits that provider's tool/verb surface. Native LAN/public listening is
unsupported and refused by default, and `SHELLX_CUT_ALLOW_NON_LOCAL=1` does not
add Cut authentication. Remote use requires an independently authenticated and
authorized SSH/VPN/ShellX broker or equivalent transport; without it, refuse
remote access. See `docs/public/shellx-cut-threat-model.md`.

**Envelope (every verb):**
`{ok, result?, op_ids?, project_revision?, warnings?[], error?{code, message, clip_id?, at_ms?, cause, suggested_action?}}`

- `warnings[]` carries non-fatal guardrail findings in-band (e.g. preflight
  auto-conform); integrity violations hard-error instead.
- Errors are actionable — `cause` + `suggested_action` tell you the next move;
  read them, don't retry blind.
- Every mutating verb accepts optional `rationale: string`, stored
  verbatim on the op record.
- Every args schema advertises optional `request_id` and `expected_revision`.
  For op-emitting mutations, reuse the same caller/request/payload after a lost
  response to receive the original durable envelope; changed payloads conflict.
  `expected_revision` requires `request_id` and atomically guards the first op.
  Read the current revision from `project.state`, `project.ops`, or the prior
  mutation envelope.

**Job model:** long-running verbs (`media.transcribe`,
`media.perception`, `render.final`, `verify.judge`, and the `media.import`
chain) return `{job_id}`. Poll `jobs.status {job_id}` (2–5 s, not a hot loop)
or watch WS `job_progress` events.

**Path fencing:** file-writing verbs (`render.final{path}`,
`export.*{path}`) canonicalize the output path and refuse traversal, symlinked
targets, writes outside the project/outputs dir, and non-media/sidecar
suffixes. Omit `path` to get the safe default location.

Columns: **Ops** = appends operation record(s) to `ops.jsonl`; **Job** =
returns `{job_id}` (poll `jobs.status` or watch WS `job_progress`).

  the pass would remove >80% of the timeline — near-total removal usually

## recipe (declarative pipeline manifests: named, gated workflows over the existing verbs)

A **recipe** is an ordered list of **stages**, each a `{verb, args, optional gate}`, parameterised by named params the stage args interpolate as exact `"{{param}}"` placeholders. Built-ins live in `schema/recipes.json` (validated at build: every referenced verb/check/fact/param must be real — drift fails the build). Built-in recipes: **`first-project`** (transcribe → measure pauses → conservative silence cut → captions → checked render, with a bundled synthetic sample available from `project.create`), **`edit-for-clarity`** (preview-first transcribe → pause analysis → conservative retake cleanup → filler removal → intensity-controlled pause tightening, no forced render), **`podcast-repurpose`** (transcribe → remove_silences → remove_fillers → cleanup_voice → captions → render@target LUFS), **`talking-head-cleanup`** (the light pass, standard render), **`screen-demo-polish`** (transcribe → remove_silences → trim_edges → captions → render with the `silent_screen_demo` verifier profile), **`phone-clip-cleanup`** (phone/camera cleanup at social loudness), **`social-short-bundle`** (render.bundle for 9:16/1:1/16:9), **`area-privacy-mask`** (edit.add_mask wrapper), **`add-captions`** (transcribe → captions), **`youtube-export`** and **`tiktok-export`** (export.publish wrappers).

## screen_record (Recording Studio)

`screen_record.*` is the in-process ShellX Record integration. `doctor` reports
`screen_capture:ok` only after a bounded, discarded frame reached Cut; it never
persists image data and reports `unknown` (not ready) when a non-disruptive proof
would risk an OS picker or permission prompt. `start`/`stop` drive live screen/audio capture;
`studio_event` appends timed background/marker metadata beside the capture;
`autoedit` writes an EditPlan; `polish` is an orchestrator that bakes and
imports the result under an auto-checkpoint; `export` writes a fenced file
without touching the timeline. Live camera capture is unavailable in this
release. Camera composition remains a downstream path for an existing
project-local camera file passed to `autoedit`.

Open-ended capture is supported: omit `duration_ms` and call `screen_record.stop`
when done. Each capture lives under
`<project>/cache/screen_record/<capture_id>/` with `project.json`,
`events.json`, optional `studio-events.json`, and optional raw streams
(`source.mp4`, `mic.wav`, `system.wav`). Live capture emits no `webcam_video`
in this release. Microphone and system-audio workers stream into bounded
same-directory partial WAVs and publish only after
successful finalization; if classic WAV capacity is reached, the shared capture
ends before audio can be silently truncated or corrupted.

`screen_record.stop` has a finite work-derived wait, not an arbitrary short
window: it uses twice the declared or durable journal-observed capture span plus
15 seconds (45 seconds minimum; 15 minutes maximum). A timeout remains an
actionable failure, but a valid 4K checkpoint stitch is not reported as failed
merely because it outlives a fixed 30-second poll.

Crash recovery never uses an open encoder container. Backends append only fully
finalized and decoded checkpoint segments to a synced manifest; restart scans may
salvage only a dead capture's contiguous verified prefix to `recovered.mp4`.
Normal `source.mp4` materializes measured encoder-restart gaps and sparse native-segment
delivery time as cloned video frames, so it stays on the same elapsed clock as events and
padded/offset audio. Query recovery receipts
with the read-only, project-scoped `screen_record.recovery_status`; it is paginated
by an exact emitted capture id (unknown ids are rejected) and never accepts or returns a cache path.

On macOS 14.2 or newer, ScreenCaptureKit video and the Core Audio system-audio
tap use separate TCC permissions. The tap stops at the video capture boundary
before checkpoint stitch/finalization work begins, then writes only its real
captured PCM with measured first-callback padding—never a post-hoc trimmed tail.
Drive native capture through the installed
signed app, approve Screen Recording and Audio Capture on first use, and restart
Cut after granting a prompt before retrying. A successful system-audio capture
publishes `system.wav`; `screen_record.stop` reports it as
`raw_streams.system`. `raw_has_system` is true only when `mux_raw:true` also
included that stream in the optional combined `raw_path`.

On Linux, `system_audio:true` captures the native PipeWire default-sink monitor.
Its first nonempty packet is measured on the capture clock before WAV I/O, so a
finalized no-packet WAV is explicitly null-timed and not placed automatically;
PipeWire connection, format, or capture failure removes the partial WAV.

| `library.add_to_project` | `{id}` | the `media.import` result `{asset_id, job_id, op, capture_manifest?}` (probe lands async via the import's `enrich_job`) — import a library asset into the OPEN project, reusing `media.import` (hash/probe/proxy/transcribe/perception + auto-place when the timeline is empty), then place it with `edit.insert`. Also bumps the use counter. Requires an open project; errors if the linked original has gone missing (re-add it, or use an item stored as a Library copy) |
| `library.folder_add` | `{name}` | `{added: bool, folders:[string]}` — create an organization folder; no-op (`added:false`) if it already exists |
| `library.folder_rename` | `{old, new}` | `{renamed: bool, folders:[string]}` — rename a folder + re-point every item under it; `renamed:false` if `old` is unknown or `new` is empty/taken |
| `library.folder_remove` | `{name}` | `{removed: bool, folders:[string]}` — remove a folder; its items are un-foldered (moved to root, NOT deleted) |

## events (WS `GET /api/events`)

`{type: op_applied | job_progress | render_done | receipt_ready | project_changed | ui_state | doctor_updated, ...}`. An `op_applied` frame carries `{revision, from_revision, delta:{kind:"op",count:1}}`; compare it with the applied revision, then pull `project.state{since_revision}`. The stream is best-effort: a gap gets the bounded delta when lossless, otherwise an explicit snapshot fallback.

`project_changed` carries `{open, name?}` whenever a project is created, opened,
or closed through REST, CLI, MCP, or the UI. Visible clients use it to refresh
their project workspace; agents should use it rather than assuming a workspace
transition appends an `op_applied` record.

On reconnect, a `project.state` error with code `no_project` confirms the active
project was closed: discard any saved `project.ops` cursor and in-flight page
before resetting project-scoped state. A transport or other transient state-read
failure is not proof of closure, so retain cached state and retry.

`doctor_updated {report}` fires when the environment doctor's capabilities
change (startup scan, `system.doctor{refresh:true}`, or a completed
`system.fetch_tool`) — the start wizard + status-bar environment chip re-render
off it.

Subscribe instead of polling where possible. Ordering guarantee:
`receipt_ready` always follows `render_done` — key on `receipt_ready`; it is
the signal that a RenderReceipt exists to read.

`receipt_ready` is **re-emitted** when `verify.judge` attaches its review to
an existing receipt (no separate judge event type — the second emission is
distinguishable by `receipt.judge` presence). `receipt.pass` stays
checks-only; the judge verdict lives at `receipt.judge.review.verdict` and
never flips an instrument check.

## Operation record shape (what your ops look like in the log)

```json
{"op_id":"op_000123","ts":"2000-01-01T12:00:00.000Z",
 "actor":{"kind":"agent","name":"assistant","via":"mcp"},
 "verb":"transcript.cut_words","args":{"asset":"a1","word_range":[114,131]},
 "rationale":"filler run 'um, so, like' (words 114-131)",
 "effects":[{"track":"v1","detail":{"removed_ms":[63200,64900]}}],
 "status":"applied"}
```

Fresh records omit `inverse`: undo/reject/revert/undo/redo recompute a journal
prefix and persist their materialized result in effects. Pre-recompute journals
may contain an optional snapshot-era `inverse`; it is retained only so those
historic records and their old `edit.restore` entries replay exactly.
`include_inverse?: boolean` remains a **deprecated v0.6 compatibility option**
for REST/CLI/MCP callers. It is validated but has no effect for fresh records,
which have no inverse payload to include.

## Clip shapes on a track (`track.clips[]`)

A track's `clips` array holds three disjoint, **untagged** JSON shapes — tell
them apart by their fields (or the `kind` literal on a gap):

| Shape | Identifying fields | Has `id`? |
|---|---|---|
| **media** | `id`, `asset`, `src_in_ms`, `src_out_ms` (+ optional `transform`/`crop`/`fade`/`xfade_in_ms`/`gain_db`/`effects`) | **yes** |
| **caption** | `id`, `text`, `range_ms` (+ optional `style_ref`) | **yes** |
| **gap** | `kind:"gap"`, `duration_ms` | **NO** |

**Invariant (regression behavior): gap clips are ANONYMOUS — `{"kind":"gap","duration_ms":N}`,
no `id` field.** Gaps are inserted automatically (a ripple `edit.insert` /
`edit.move` splices a gap into sibling tracks; `edit.ripple_delete{ripple:false}`
leaves one) and are addressed by POSITION, never by id — so they carry none.
**If you iterate `track.clips` and key on `clip["id"]`, special-case gaps first**
(`clip.get("kind") == "gap"` → skip, or read `duration_ms`); a blind `clip["id"]`
will KeyError/`undefined` on a gap. This is by design, not an omission — the
engine's own `Clip::id()` returns `None` for a gap.

Ops are immutable. Ctrl+Z/Ctrl+Shift+Z append `project.undo`/`project.redo` nav
ops; review rejection appends a new `edit.restore` op referencing the old one
(never rewrites history). The DEFAULT `edit.restore` (`mode:"tip"`) recomputes
the target's pre-op journal prefix, which is why it refuses non-tip targets (a
tip restore of an old op would roll back every later edit;
the server guards this with a `guardrail` error and points at the rebase/revert
paths). To selectively undo an OLDER op while keeping the later ones, use
`edit.restore {op_id, mode:"rebase"}`: it reproduces the timeline as if that op
never happened via an **id-pinned skip-replay** (every surviving op's allocated
clip/marker/track ids stay stable), and is **refused with a `guardrail` error
naming the dependents** when a later op references an id the target created —
only provably-independent ops are rebased out (a half-working rebase is worse
than none). `project.revert{to}` remains the full rollback-to-a-point path.
Checkpoints are pointers into the log; `project.json` is a rebuildable cache.
